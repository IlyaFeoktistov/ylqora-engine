# Ввод

[English version](input.md)

Клавиатура, мышь, следом геймпады, и действия ввода, которые игры читают
вместо клавиш.

Пометки статуса: см. [README](README.ru.md).

## Сырой ввод [done]

- `Input` - состояние одного кадра: зажатые клавиши и кнопки мыши, нажатые и
  отпущенные в этом кадре, положение мыши, её сдвиг и колесо. Игры его
  только читают.
- Пишет в него только `InputFeeder`: окно передаёт туда события системы.
  Кадр начинается с `beginFrame` (то, что длилось один кадр, сбрасывается);
  когда окно теряет фокус, всё отпускается, чтобы клавиша, отпущенная в
  другом окне, не осталась зажатой.
- Клавиши физические: `W` остаётся `W` в любой раскладке. Список клавиш и
  кнопок мыши записан один раз (`YQLORA_KEYS`, `YQLORA_MOUSE_BUTTONS` в
  `Key.hpp`); перечисления и имена (`kKeyNames`, `kMouseButtonNames`)
  получаются из него.
- Перенос мыши: пока летит камера редактора, курсор, дошедший до края окна,
  переносится к противоположному краю, а сдвиг считается без скачка
  (`Window::setMouseWrapping`).
- В редакторе у копии Play свой `Input`; ввод приложения она видит, только
  пока окно "Игра" в фокусе (см. [кадр](frame.ru.md)).

## Действия ввода [done]

- Раздел Input настроек проекта (`InputSettings`) перечисляет действия. У
  действия есть имя, вид и привязки:
  - **кнопка** зажата, пока зажата любая привязка; нажатие и отпускание
    считаются по смене этого с прошлого кадра, поэтому вторая клавиша,
    которая держит действие, не делает его отпущенным;
  - **ось** - сумма множителей зажатых привязок, ограниченная -1..1: `D` с 1
    и `A` с -1 дают горизонтальную ось.
- Привязка называет орган управления: клавишу (`"Space"`) или кнопку мыши
  (`"MouseLeft"`). В файл пишутся имена, а не числа, поэтому порядок клавиш в
  коде можно менять. Неизвестное имя пропускается.
- Игры спрашивают действия, а не клавиши: `input.isActionDown("Jump")`,
  `wasActionPressed`, `wasActionReleased`, `actionValue("MoveX")`.
  Неизвестное действие не зажато и даёт 0. Переназначение клавиш никогда не
  трогает код игры.
- Действия считаются на стадии ввода, сразу после событий окна, по
  настройкам открытого проекта (`InputFeeder::updateActions`); правка
  настроек действует со следующего кадра.
- В окне настроек привязка задаётся нажатием: кнопка привязки ждёт
  следующего нажатия клавиши или кнопки мыши, Escape отменяет.

## Геймпады [next]

- Кнопки и стики геймпада через SDL, с мёртвой зоной; они становятся
  органами управления привязок, как клавиши (`"GamepadSouth"`,
  `"LeftStickX"`), стики дают значения осей.
