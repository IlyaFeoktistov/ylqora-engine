# Проект и форматы файлов

[English version](project.md)

Что лежит в папке проекта, как пишутся его файлы и как проект переходит на
новый формат. Разделы настроек - в [настройках проекта](project-settings.ru.md),
ID ресурсов - в [ресурсах](resources.ru.md).

Пометки статуса: см. [README](README.ru.md).

## Папка проекта [done]

```
MyGame/
|-- project.yqlora          имя проекта, версия формата, версия движка
|-- settings/               по файлу на раздел настроек
|   |-- general.json
|   |-- time.json
|   `-- ...
|-- .build/                 библиотека игры: game.dll / libgame.so
|-- main.yscene             сцены, где угодно в папке
|-- main.yscene.meta        ID ресурса для файла рядом
`-- ...                     остальные ресурсы со своими .meta
```

- `project.yqlora` и `settings/` - не ресурсы: обход ресурсов их пропускает
  (`Project::reservedNames`), панель "Файлы" их не показывает и не даёт
  переименовать или удалить.
- Скрытые файлы и папки (с точки в начале) тоже пропускаются, поэтому
  результат сборки в `.build/` никогда не ресурс; редактор загружает оттуда
  библиотеку игры (см. [скрипты](scripting.ru.md)), а в шаге 3 собирает её
  туда же.
- Проект - это `Project` в движке: он нужен и редактору, и запуску игры
  (шаг 9). Создание, импорт и удаление папки проекта - дело редактора
  (`ProjectSetup`, `ProjectManager`).

## Файлы [done]

Все файлы движка - JSON с отступами, чтобы разница в системе контроля версий
читалась. У каждого файла есть `version` - версия его формата.

`project.yqlora`:

```json
{
    "engine": "0.0.1",
    "name": "MyGame",
    "version": 1
}
```

`settings/<раздел>.json` (см. [настройки проекта](project-settings.ru.md)):

```json
{
    "values": {
        "gameName": "MyGame",
        "startupScene": "9bf87a121dc2ad5c"
    },
    "version": 1
}
```

`*.yscene`: корневой узел с его свойствами, компонентами и детьми.

```json
{
    "root": {
        "type": "Node3D",
        "id": "da9dc314563ffd36",
        "properties": {"name": "Root", "active": true},
        "components": [{"type": "Transform3D", "properties": {"position": [0.0, 0.0, 0.0]}}],
        "children": []
    },
    "version": 1
}
```

- Свойства пишет реестр типов: каждое зарегистрированное свойство типа, под
  своим именем (см. [реестр типов](reflection.ru.md)). Недостающее свойство
  остаётся значением по умолчанию. Неизвестное свойство компонента хранится
  при компоненте и пишется обратно (`UnknownProperties`), а компонент
  неизвестного типа становится заглушкой со своим JSON (`MissingComponent`),
  поэтому добавить или убрать поле или скрипт в коде можно, сохранённые
  данные не ломаются и не теряются (см. [скрипты](scripting.ru.md)).
  Неизвестные свойства узлов пропускаются: типы узлов принадлежат движку, а
  смена его формата идёт через переводы.
- 64-битные ID (узлов, ресурсов) пишутся строкой из 16 шестнадцатеричных
  цифр: многие инструменты читают числа JSON только до 2^53 и молча портили
  бы их.
- Перечисления пишутся именем, поэтому порядок значений в C++ можно менять.
- Двоичный формат сцен для собранной игры придёт с шагом 9; JSON остаётся
  исходным форматом для редактора и системы контроля версий
  **[planned, step 9]**.

## Версии форматов [done]

- У каждого вида файлов свой формат (`FileFormat`): имя, первая версия и
  список переводов. Текущая версия выводится из списка: добавил перевод -
  версия выросла. Перевод сам объявляет ключи старой версии, поэтому
  переименование ключа потом не меняет старые переводы.
- Чтение файла говорит, текущая ли у него версия, старая (можно перевести),
  новее (сохранён более новым движком) или неподдерживаемая (версии нет или
  перевода с неё нет).
- Пока пользователей нет, все форматы остаются версии 1 без обратной
  совместимости. Когда формат меняется, у него появляется перевод и тест, а
  не молчаливое чтение старого вида.

## Перевод проекта [done]

- Менеджер проектов показывает версию движка каждого проекта и самого
  движка. Проект старого формата открывается только через окно "Перевести
  проект"; после перевода старые движки его не откроют. Проект более нового
  движка или без версии не открывается, с объяснением.
- `upgradeProject` сначала читает и переводит в памяти все сцены и все файлы
  настроек; если один не читается, ничего не пишется. Потом пишет настройки,
  сцены и последним `project.yqlora`. Пока файл проекта старый, проект снова
  предложат перевести, а повторный перевод уже переведённого файла ничего не
  меняет, поэтому прерванный перевод просто повторяется.
