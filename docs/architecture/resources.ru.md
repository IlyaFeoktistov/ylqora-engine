# Ресурсы

[English version](resources.md)

Файлы проекта, которыми пользуется игра: сейчас сцены, со своими шагами -
меши, текстуры, материалы, шейдеры и звуки. Где они лежат и форматы файлов -
в [проекте и форматах файлов](project.ru.md).

Пометки статуса: см. [README](README.ru.md).

## ID ресурсов [done]

- На ресурс ссылаются по `ResourceId`, 64-битному числу, а не по пути:
  переименованный или перенесённый файл сохраняет все ссылки на себя
  (стартовая сцена, меш у `MeshRenderer`).
- ID лежит в файле `.meta` рядом с ресурсом (`level.yscene.meta` хранит
  `{"id": "...", "version": 1}`), поэтому он едет вместе с файлом в системе
  контроля версий. `.meta` без версии формата или с битым ID не читается, и
  файл получает новый ID.
- `ResourceDatabase` хранит обе стороны, ID -> путь и путь -> ID, все пути от
  папки проекта.
- Новый ID - 64 случайных бита, поэтому у двух проектов один и тот же ID
  практически не выпадет; он всегда не меньше `builtin::kFirstProjectId`.
- **Встроенные ресурсы** (меши куба, сферы и плоскости) имеют маленькие
  постоянные ID меньше `kFirstProjectId` и не имеют файла; ID проекта с ними
  не пересекается.
- В свойстве ссылка - это `ResourceRef`; 0 значит "нет".

## Как ID остаются верными [done]

- `scan` обходит папку проекта при открытии проекта. Файл без `.meta`
  получает её с новым ID. Если ID повторяется (файл скопировали вместе с
  `.meta`), копия получает новый. Скрытые файлы и занятые имена
  (`project.yqlora`, `settings/`) - не ресурсы.
- О своих изменениях редактор сообщает базе сам: `add` для нового файла,
  `moved` после переименования или переноса (`.meta` едет следом, ID
  остаются), `removed` после удаления (`.meta` удаляется, ID забывается).
- Изменения, сделанные мимо редактора, подхватит следующий `scan`.

## Меши и текстуры из файлов [planned, step 4]

### Решения

- **Ресурс - сам исходный файл**, как в Godot и Unity: `.glb`, `.gltf`,
  `.png`, `.jpg` лежат где угодно в проекте и видны в "Файлах". Движок
  читает сам исходный файл; кэш импорта и двоичный формат придут с шагом 9,
  между исходным файлом и `ResourceCache`, без изменения интерфейса ресурсов.
- **Библиотеки**: cgltf (MIT) для glTF 2.0, stb_image (public domain или MIT)
  для PNG, JPG, TGA, BMP, из файла и из памяти (картинки внутри GLB позже).
  Без FBX (закрытый формат) и OBJ (его покрывает glTF).
- **Три уровня, не смешиваются**: исходный файл, загруженные данные в
  `ResourceCache` (`MeshData`, `TextureData`), копии в видеопамяти в бэкенде.
  Файлы читает только кэш, видеопамять знает только бэкенд.
- **Загрузчики по расширению.** Новый вид ресурса - новый загрузчик, больше
  ничего не меняется. Встроенные меши лежат в том же кэше со своими
  постоянными ID; `findBuiltinMesh` уходит.
- **Загрузка синхронная**, при первом обращении. Фоновая - позже.
- **Не в шаге 4**: скелет, анимация, морфинг, камеры и свет из glTF, сжатые
  текстуры (KTX2), PBR из glTF (шаг 5).

### ID вложенных ресурсов

В файле может быть несколько ресурсов (меши `.glb`). У каждого свой
`ResourceId`, поэтому `ResourceRef` остаётся одним 64-битным числом.

```json
{
    "id": "9bf87a121dc2ad5c",
    "import": {"scale": 1.0},
    "subresources": {
        "mesh:Door": "4c1e07a95b3d2f60",
        "mesh:Door#1": "a07f3b9e21c8d415",
        "mesh:#2": "e51d90c4b7a2f386"
    },
    "version": 1
}
```

- Вложенный ID - 64 случайных бита, создаётся один раз и хранится в
  `.meta`, из имени не вычисляется. Имя - только ключ, по которому элемент
  файла находит свою запись.
- Ключ: вид, имя и номер элемента среди элементов с тем же именем (`Door`,
  `Door#1`); элемент без имени - по своему индексу в файле (`#2`), поэтому
  удаление элемента перед ним даёт ему новый ключ. Ключ, уже выданный в
  файле, получает следующий номер, поэтому ключи не повторяются даже с `#`
  в имени (`SubresourceKeys`).
- Перевыгрузка из Blender: элементы, чей ключ нашёлся, сохраняют ID, новые
  получают новые. Запись элемента, которого в файле больше нет, остаётся в
  `.meta`, ссылки на него показывают "нет в файле", а ID вернётся, если
  вернётся элемент.
- Переименование и перенос: `.meta` едет за файлом, все ID остаются. Копия
  (повтор ID файла, найденный `scan`) получает новый ID файла и новые
  вложенные ID.
- `ResourceDatabase` знает для каждого ID файл и ключ внутри него.
- У `.meta` появляется версия формата (`FileFormat`), версия 1.

### Кэш и ревизии

- У загруженного ресурса есть ревизия. Кэш видеопамяти в бэкенде хранит
  копии по ID и ревизии: новая ревизия заменяет старую копию, а старая
  освобождается, когда ею больше ничего не рисуется.
- Перезагрузка (файл изменился на диске или "Применить" у настроек импорта)
  сначала загружает новые данные, потом проверяет их, потом заменяет запись
  и повышает ревизию. Старые данные не уничтожаются до загрузки новых.
- Неудачная загрузка переводит ресурс в состояние "ошибка" с её текстом:
  старые данные не показываются под видом текущих. Удалённый файл переводит
  ресурс в состояние "нет файла"; ссылки остаются и снова работают, когда
  файл вернётся.
- Ссылка на пустой, отсутствующий или битый ресурс ничего не рисует; в лог
  одно сообщение на ресурс, инспектор показывает состояние.
- Данные из кэша их пользователи не держат между кадрами: `FrameData` и
  выбор мышью берут их заново каждый кадр, поэтому после перезагрузки не
  остаётся висячих указателей.

### Меши

- `Vertex`: позиция, нормаль, `uv0`. Касательные - с картами нормалей в
  шаге 5.
- В `MeshData` есть подмеши (диапазоны индексов, по одному на примитив
  glTF) и границы (AABB, для выбора мышью, позже для отсечения). У подмеша
  постоянный индекс: это слот материала шага 5, и он хранит индекс
  материала glTF своего примитива (или "нет"), поэтому шаг 5 импортирует
  материалы без смены контракта загрузчика.
- Загрузчик glTF читает данные через аксессоры cgltf, поэтому работают
  перемежающиеся буферы, разреженные аксессоры, нормализованные целые,
  внешние буферы, блоки GLB, отсутствие индексов и все типы компонентов.
  Принимается только режим TRIANGLES, остальные отклоняются с сообщением.
  Отсутствующие нормали считаются сглаженными, суммой нормалей граней по
  общим вершинам; вершины, разделённые в файле, остаются разделёнными.
- Описание модели хранит дерево узлов файла с локальными трансформами и
  ссылками на меши. Один меш у нескольких узлов - один ресурс с несколькими
  ссылками, геометрия не копируется.
- Настройка импорта: масштаб.

### Текстуры

- `TextureData`: RGBA8, ширина, высота. Настройки импорта: цветовое
  пространство (sRGB для цвета, Linear для данных: нормали, шероховатость,
  металличность), фильтр, повтор, мипмапы. Настройки - запись, поэтому новые
  добавляются без смены загрузчика.
- На меши текстуры ложатся только через материалы, в шаге 5. В шаге 4
  текстура используется как иконка игры (раздел General).

### Фазы шага 4

0. Хвосты шага 3. Модуль игры регистрирует только скрипты, поэтому при
   его перезагрузке пересоздавать нечего: ни систем, ни разделов настроек.
   Контракт записан, а пересоздание переехало в [плагины](plugins.ru.md),
   чьи модули будут их регистрировать **[done]**.
1. `ResourceCache` и интерфейс загрузчика, встроенные меши в нём;
   `FrameBuilder` и выбор мышью берут меши из кэша; `findBuiltinMesh`
   уходит; `uv0`, подмеши, AABB; кэш видеопамяти по ID и ревизии. Снаружи
   ничего не меняется **[done]**. Кэш принадлежит `EngineServices`
   (`services.resources()`), и открытие проекта там же передаёт проект
   кэшу; у копии Play свой ввод, но общий кэш, поэтому файлы не читаются
   второй раз. Кэш видеопамяти - один шаблон для всех бэкендов и ресурсов
   (`GpuResourceCache`): копия, которой не рисовали 120 кадров,
   освобождается.
2. Вложенные ID и формат `.meta` (версия, `import`, `subresources`)
   **[done]**. `ResourceDatabase::assignSubresources` выдаёт ID ключам,
   которые вернул загрузчик, и пишет `.meta` один раз; `fileOf`, `key`,
   `subresources`; настройки импорта - объект JSON, хранится текстом
   (`importSettings`, `setImportSettings`) и приходит загрузчику в
   `LoadRequest::import`. Кэш записывает ID при загрузке, поэтому держит
   проект изменяемым.
3. Меши glTF: загрузчик, описание модели, масштаб **[done]**.
   `GltfLoader` (`yqlora/import/`) даёт `ModelData` для файла (узлы с
   локальными положением, поворотом, масштабом, индексом меша и детьми;
   ключи мешей) и по `MeshData` на каждый меш файла. Загрузчики движка
   добавляет `addEngineLoaders` при создании `EngineServices`. cgltf читает
   внешние буферы через функцию чтения движка, поэтому пути не из ASCII
   работают и на Windows.
4. Текстуры: загрузчик, настройки импорта, текстура в видеопамяти, иконка
   игры **[done]**. `ImageLoader` (stb_image, байты читает движок) даёт
   `TextureData`; загрузчик ещё называет вид своего файла
   (`ResourceLoader::kind`, `ResourceCache::kindOf`), поэтому редактор
   перечисляет текстуры, не читая файлы. Настройки импорта и их имена - в
   `TextureImport`. `GlTexture` берёт строки сверху, поэтому
   `uv0 = (0, 0)` - левый верхний угол без переворота. `Renderer::uiTexture`
   показывает текстуру в интерфейсе с цветами файла (без перевода из sRGB:
   ImGui рисует в обычный буфер); поле иконки в General показывает превью.
5. Редактор: иконки в "Файлах"; инспектор файла ресурса (меши с числом
   вершин, треугольников и подмешей; превью и размер текстуры; настройки
   импорта с кнопкой "Применить"); меши проекта в списке `MeshRenderer` по
   файлам; модель, перетащенная из "Файлов" в дерево или окно вида, создаёт
   своё дерево узлов одним шагом отмены; перетаскивание меша на поле меша;
   изменённые файлы перезагружаются, когда окно редактора получает фокус.
6. Перетаскивание узлов в дереве с вопросом "Сохранить положение в мире?"
   (см. [сцену](scene.ru.md)), родитель и трансформ одним шагом отмены.
7. Привязка при перемещении: по сетке, по вершинам, на поверхность, с
   кнопками на панели окна вида и клавишами (см. [редактор](editor.ru.md)).
8. Документы: этот, проект (`.meta`), рендер (формат вершин, подмеши),
   редактор, руководство "Импорт модели", README.

Тесты, кроме модульных тестов каждой части:

- 1: перезагрузка повышает ревизию; старая копия в видеопамяти
  освобождается; после перезагрузки нет висячих данных (asan).
- 2: элементы с одинаковыми именами; переименование сохраняет ID; копия
  получает новые ID; перевыгрузка сохраняет ID; запись убранного элемента
  остаётся.
- 3: перемежающиеся буферы; GLB с несколькими мешами; один меш у
  нескольких узлов; нет нормалей; битые данные и режим не TRIANGLES дают
  ошибку, а не падение.
- 4: PNG с прозрачностью; JPG; sRGB и Linear; повторное применение
  настроек импорта повышает ревизию.
- 5: модель с вложенными узлами в сцену; перевыгрузка сохраняет ссылки;
  сохранение и повторное открытие сцены; удаление исходного файла при
  существующих ссылках.
