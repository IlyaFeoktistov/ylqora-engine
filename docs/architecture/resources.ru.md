# Ресурсы

[English version](resources.md)

Файлы проекта, которыми пользуется игра: сейчас сцены, со своими шагами -
меши, текстуры, материалы, шейдеры и звуки. Где они лежат и форматы файлов -
в [проекте и форматах файлов](project.ru.md).

Пометки статуса: см. [README](README.ru.md).

## ID ресурсов [done]

- На ресурс ссылаются по `ResourceId`, 64-битному числу, а не по пути:
  переименованный или перенесённый файл сохраняет все ссылки на себя
  (стартовая сцена, меш у `MeshRenderer`).
- ID лежит в файле `.meta` рядом с ресурсом (`level.yscene.meta` хранит
  `{"id": "..."}`), поэтому он едет вместе с файлом в системе контроля версий.
- `ResourceDatabase` хранит обе стороны, ID -> путь и путь -> ID, все пути от
  папки проекта.
- Новый ID - 64 случайных бита, поэтому у двух проектов один и тот же ID
  практически не выпадет; он всегда не меньше `builtin::kFirstProjectId`.
- **Встроенные ресурсы** (меши куба, сферы и плоскости) имеют маленькие
  постоянные ID меньше `kFirstProjectId` и не имеют файла; ID проекта с ними
  не пересекается.
- В свойстве ссылка - это `ResourceRef`; 0 значит "нет".

## Как ID остаются верными [done]

- `scan` обходит папку проекта при открытии проекта. Файл без `.meta`
  получает её с новым ID. Если ID повторяется (файл скопировали вместе с
  `.meta`), копия получает новый. Скрытые файлы и занятые имена
  (`project.yqlora`, `settings/`) - не ресурсы.
- О своих изменениях редактор сообщает базе сам: `add` для нового файла,
  `moved` после переименования или переноса (`.meta` едет следом, ID
  остаются), `removed` после удаления (`.meta` удаляется, ID забывается).
- Изменения, сделанные мимо редактора, подхватит следующий `scan`.
