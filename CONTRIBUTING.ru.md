# Участие в разработке

[English version](CONTRIBUTING.md)

Как пишется код Yqlora. Сама архитектура - в
[docs/architecture](docs/architecture/README.ru.md).

## Перед коммитом

```bash
make hooks        # один раз: перед каждым коммитом форматирует добавленные файлы C++ и гоняет тесты
make format       # clang-format 23.1.3 по всем исходникам
make test         # сборка и тесты
make sanitize     # тесты с AddressSanitizer и UBSan (Linux)
make docs-check   # английские и русские документы совпадают
```

CI проверяет форматирование, документы, тесты на Linux (и с санитайзерами) и
на Windows (MSYS2 UCRT64). Правка проверяется на обеих системах до того, как
её примут.

## Раскладка

- Публичные заголовки в `include/`, заголовки только для движка и редактора -
  в `internal/`, в `src/` только файлы `.cpp`. Так в каждой части: `engine/`,
  `editor/` (логика), `editor/ui/` (интерфейс), `backends/opengl/`.
- Заголовки подключаются как `"yqlora/<часть>/X.hpp"`, никогда по
  относительному пути.
- Каждая подсистема - своя папка и сама регистрирует свои типы.
- Логика редактора никогда не подключает ImGui; интерфейс только вызывает
  логику. Цвета и размеры интерфейса берутся из `assets/themes`, значки -
  только из шрифта иконок Lucide.

## Устройство

- **Одна ответственность.** Класс, служба или функция делает одно дело и
  сразу кладётся в свою подсистему и папку, а не "пока сюда". Движок растёт
  добавлением частей, а не их переписыванием.
- **Один источник знания.** Список типов, имя, правило записаны в одном
  месте, всё остальное выводится из него (имя типа из `YQLORA_TYPE`, тип
  свойства из `std::variant`, поля записи из `YQLORA_RECORD`). С документами
  так же: решение живёт в одном документе.
- **Без магических значений.** Числа и строки со смыслом (размеры, пределы,
  ключи JSON, имена файлов, ID действий) - именованные константы, по одному
  набору на формат или подсистему, общие для чтения и записи.
- **Свободные функции или методы.** Метод, если нужны закрытые данные или
  инварианты класса; иначе свободная функция в пространстве имён. Никакого
  скрытого глобального состояния за свободными функциями; лог и `tr()` -
  единственные службы движка с общей точкой доступа.
- **Пространства имён.** Классы живут в `yqlora` (редактор - в
  `yqlora::editor`, бэкенд OpenGL - в `yqlora::opengl`); вложенное
  пространство - для группы свободных функций и констант без владельца
  (`math`, `log`).
- **Форматы.** Смена формата файла идёт вместе с переводом и тестом (см.
  [проект и форматы файлов](docs/architecture/project.ru.md)).

## Стиль кода

- Форматирование решает `.clang-format`. Сверх него: тело функции никогда не
  пишется в одну строку, даже у геттера или пустого `{}`; перед `return`
  пустая строка, если это не первая строка блока.
- Комментарии только там, где они что-то добавляют: неочевидная причина,
  ограничение, ловушка, контракт, который не следует из имени. Код словами не
  пересказывать.
- В комментариях, документах и сообщениях коммитов только символы с обычной
  клавиатуры: прямые кавычки, `-` вместо тире, `->` вместо стрелок. Другие
  символы в коде - только escape-кодами (`"\uE1C3"`).
- Примеры в комментариях и тестах правдоподобны для движка (`Health` - будущий
  скрипт, а не встроенный компонент).

## Документы

- Каждый документ - пара: `X.md` на английском и `X.ru.md` на русском с теми
  же заголовками, блоками кода и пометками статуса; обе меняются в одном
  коммите.
- Документ меняется вместе с кодом, который описывает; пометки статуса
  (**[done]**, **[next]**, **[planned, step N]**) говорят, что сделано.

## Коммиты

- Одна короткая строка на русском, без служебных строк в конце.
- Одна логическая правка на коммит; форматирование и переносы - отдельно от
  изменения поведения.
